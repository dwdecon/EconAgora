一个学期结束后，研究项目最容易丢失的往往不是 PDF 或代码，而是决策的上下文：为什么采用这个识别策略？那个变量为什么被放弃？这份数据口径是谁和审稿人博弈后的结果？没有这些上下文，新学期加入的成员只能被动接受旧结论，或在反复追问中重新发明轮子。

向量检索是常见的 Agent 记忆方案，但它主要解决“文本相似”问题，并不天然保存“为什么这样决策”。Lilian Weng 将 Agent 记忆区分为感觉记忆、短期记忆与长期记忆，并指出向量检索只是长期记忆的一种载体[^1]。Packer 等人在 MemGPT 中提出分层记忆架构，把上下文、外部存储与分层归档分开管理[^2]。Park 等人生成式 Agent 的 memory stream、reflection 与 retrieval 机制则进一步说明，长期经验需要被结构化为可回忆事件[^3]。LangChain 的 Memory 文档也强调，不同记忆类型服务于不同任务，不能一刀切[^4]。

对经济学研究而言，真正有价值的记忆系统必须把事实、判断与制度上下文分层保存，并为每条记忆设置失效条件与回链证据。

## 1. 为什么“记住所有对话”不够

把聊天记录直接 embedding 进向量库，看似保存了一切，实际带来三个问题：

- **噪声压倒信号**：讨论中的试探、错误假设和临时结论与最终判断混在一起，检索时难以区分。
- **“为什么”丢失了**：向量保存的是文本相似度，不是决策理由。新学期成员看到旧结论，无法判断其是否仍然成立。
- **失效无法追踪**：数据更新、政策背景变化、课程轮替都会让旧结论过时，但对话记录不会自动标注有效期。

因此，记忆系统不应以“保存更多对话”为目标，而应以“保存可验证的判断资产”为目标。

## 2. 把记忆分成三层：事实、判断、制度

我们建议把研究记忆拆成三层，每层使用不同的存储与检索方式。

### 2.1 事实层

保存变量定义、数据口径、来源链接、样本范围、清洗步骤。事实层要求精确、可追溯、可替换。

示例条目：

```yaml
---
memory_type: fact
name: 最低工资处理变量定义
content: 处理组为 1992 年 4 月起最低工资从 $4.25 提高至 $5.05 的新泽西州快餐店
source: card_krueger_1994_table1.md
valid_from: 2026-02-01
valid_until: 数据版本 v3.2 更新前
last_verified: 2026-02-10
---
```

### 2.2 判断层

保存为什么采用某个识别策略、为什么放弃某个变量、稳健性检验的结论是什么。判断层必须绑定证据与推理过程。

示例条目：

```yaml
---
memory_type: judgment
name: 放弃县级聚类标准误的原因
content: 样本中县级数量过少，聚类至县级会导致标准误估计不稳定；最终采用州级聚类。
reasoning: 参考 Bertrand et al. (2004) 关于聚类层级的讨论，结合样本中县数 N<50 的实际情况。
evidence: notes/clustering_decision_20260215.md
made_by: 张同学
valid_until: 样本结构发生重大变化
last_verified: 2026-02-15
---
```

### 2.3 制度层

保存导师偏好、课程目标、合作规范、审稿人风格、团队约定。制度层帮助新成员快速理解“在这个项目里怎样做事”。

示例条目：

```yaml
---
memory_type: institution
name: 导师对稳健性表格的要求
content: 所有主结果必须附三种稳健性：排除极端值、替换识别策略、替换结果变量。
source: meeting_notes_20260201.md
scope: 本学期劳动经济学专题
last_verified: 2026-02-01
---
```

三层不能混写。混写会导致检索时事实、判断与制度互相污染，降低记忆的可信度。

## 3. 记忆条目必须带时间戳和失效条件

经济学研究环境持续变化。没有失效条件的记忆，最终会变成无法质疑的教条。每条重要记忆应至少标注：

- `valid_from`：生效时间；
- `valid_until`：预期失效条件或时间；
- `last_verified`：最后验证时间；
- `source`：原始证据回链。

失效条件不是形式主义，而是给新学期交接提供审查入口。每学期开始前，团队应先做一轮“失效审查”：哪些数据已更新？哪些政策背景已变化？哪些合作规范已调整？

## 4. 最好的记忆系统能把人带回原始证据

不要让记忆层本身成为新的黑箱。每一条重要结论都应该能回链到：

- 研究笔记或会议记录；
- 数据分析脚本与输出日志；
- 原始论文或数据文件；
- 版本控制系统中的具体提交。

回链证据的好处是：当后人质疑某条记忆时，他可以直接回到产生这条记忆的工作现场，而不是只能接受或拒绝一个二手结论。

## 5. 跨学期交接的最小可行流程

学期末，建议输出一份“记忆快照”，结构如下：

```markdown
# 项目记忆快照：2025-2026 春季学期

## 未完成假设
- H1: 最低工资提高对青少年就业的负向效应在边界县设计下是否仍然成立？
- H2: 企业进入退出渠道是否被低估？

## 已验证结论
- C1: 新泽西州快餐业就业在政策后未显著下降（来源：……）
- C2: 州级聚类标准误优于县级聚类（来源：……）

## 待验证问题
- Q1: 1992 年后新泽西州其他同期政策是否造成混淆？
- Q2: 样本是否需要扩展至 2000 年以后？

## 制度更新
- 下学期改为双周组会，文献矩阵需在会前更新。
```

新学期开始后，先用这份快照进行失效审查，再决定哪些记忆可以直接继承，哪些需要重新验证。

## 6. 反模式与检查清单

常见反模式：

- 把聊天记录直接 embedding；
- 把所有结论混在一个知识库；
- 只保存“最终答案”，不保存“为什么”；
- 不标注失效条件，导致旧结论长期污染新决策。

每次存入重要记忆前，建议核对：

- [ ] 分层了吗？它属于事实、判断还是制度？
- [ ] 有失效条件吗？
- [ ] 能回链到原始证据吗？
- [ ] 有最后验证时间吗？
- [ ] 有交接仪式或快照吗？

## 7. 下一步

记忆系统解决的是“研究上下文如何跨时间保存”的问题。但要让 Agent 真正参与研究执行，还需要把提示策略、领域技能和工具调用拆成可独立演化的三层。下一篇将讨论如何用 Prompt、Skill、Tool 三层构建经济学研究 Copilot。
